# DVT2-M5B-GEMINI-EXACT

Status: measured, experimental only. `SerialCanonical` remains the default and
fallback. No Make.oct architecture, native production default, SDSL-V source,
or external HLSL byte was changed.

## Identity and static contract

GeminiExact is external HLSL at
`internal/prometheus/shaders/hlsl/external/m5b-gemini-exact.hlsl`, copied
byte-for-byte from the supplied file. Source SHA-256:
`0ebc86c1c595f03a671ddd63f25f882ae2ce70606c025a875627456038b44755`
(4,508 bytes). Although its preserved first comment makes a claim about
generation, repository provenance is external authored HLSL; it is not claimed
to be generated by SDSL-V and has not been ported to SDSL-V.

DXC 1.9.0.5347 (`dxcompiler.dll: 1.10(5347-fe261573)`) compiled exactly that
file with `dxc -spirv -T cs_6_0 -E MainTransformerJointAttentionSubgroupOwned_CS
-Fo m5b-gemini-exact.spv -fspv-target-env=vulkan1.3 -O3
m5b-gemini-exact.hlsl`. `spirv-val --target-env vulkan1.4
m5b-gemini-exact.spv` passed. SPIRV-Tools was v2026.2. The emitted SPIR-V is
6,508 bytes, SHA-256
`2414fae73dfa055e4e23c35eed17ab8c22093feb4b4c3f002c268d09e6357803`.
The checked-in disassembly is `m5b-gemini-exact.spvasm`; the native header is a
mechanical embedding of that binary.

The GeminiExact module has entry point
`MainTransformerJointAttentionSubgroupOwned_CS`, `LocalSize 256 1 1`, storage
bindings Qkv=0, Attention=1, Audit=2, and a 16-byte push constant with fields
at offsets 0/4/8/12. It retains the M5b row mapping: eight subgroup-owned rows
per workgroup, subgroup size 32, `packedRow = workgroupX * 8 + subgroup`, and
33 key groups for the fixed 1,056-token row. Its descriptor, output indexing,
push constants, group count (3,960), and 1,056-row envelope match original
M5b. The only added manifest admission facts are size 32 plus arithmetic and
shuffle support for `FMax`, `FAdd`, and shuffle; no host/resource contract was
changed.

## Admission and execution

The RTX 3070 Vulkan preflight passed with Vulkan 1.4/SPIR-V 1.6 services:
subgroup size 32; compute, arithmetic, basic, and shuffle support all true;
and subgroup-owned attention admitted. The established arbitrary-lane shuffle
proof remains the Mx5 `WaveReadLaneAt` validation; no new proof was invented.
GeminiExact has its own registry id 45 and macro
`PROMETHEUS_DVT2_M5B_GEMINI_EXACT_EXPERIMENT`; it cannot be enabled with the
original id-44 M5b macro. Both are rejected unless the existing bounded
subgroup preflight admits the device.

The bounded real M2C retained-stream MainTransformer route used the same RTX
3070, validation setting, payload cache, pinned `f332072…564a6` oracle, and
`5e-5` final-transformer relative-L2 limit for every variant. It includes the
representative layer-0 attention output/audit comparison and the existing
resident MainTransformer chain authority. Results:

| Variant | Executed | Final joint relative L2 | Finite | Result |
| --- | --- | ---: | --- | --- |
| SerialCanonical | yes | 8.38066e-7 | yes | pass |
| Original M5b | yes | 8.38066e-7 | yes | pass |
| GeminiExact | yes | 8.39396e-7 | yes | pass |

All three also passed bounded image/context-region audits and the complete
resident-chain authority (GeminiExact chain relative L2 `9.66693e-6`). No
device loss, timeout, non-finite result, admission failure, or bounds/audit
failure occurred in candidate execution. An initial SerialCanonical attempt
used the wrong local oracle revision and stopped before runtime creation
because its input/timestep files were zero bytes; it was corrected to the
repository-documented pinned revision before the successful ladder and is not
candidate evidence.

## Timing and decision

The existing correctness harness emits ten measured warm samples after the
retained streams, weights, descriptors, and pipelines are warm. A sample is
one complete `prometheus_reactor_runtime_main_transformer_execute` of the
representative layer-0 MainTransformer: Q/K rope, the attention dispatch,
projection, residual, FFN, and other recorded MainTransformer stages. It is
not an attention-dispatch-only measurement. `warm_ns` is CPU wall time;
`gpu_compute_ns` is a Vulkan timestamp-query interval from the first compute
boundary through the final compute boundary, with `timestampPeriod=1 ns` and
64 valid bits on the RTX 3070 compute queue. The log emitted all ten CPU samples
but only GPU median/mean, so raw GPU samples and their variance are unavailable.

Decision: retain GeminiExact as an isolated experimental external artifact.
Do not promote, translate, or modify it. SerialCanonical remains the production
default and fallback.
