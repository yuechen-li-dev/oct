## Stateful SDSL-V model

`RayQueryTraceClosest(Scene, Spheres, RayWords, Result, TriangleVertices)` is
a compute-only, statement-only compiler intrinsic. It is deliberately not a
copyable source-level query value: the HLSL emitter owns the mutable opaque
`RayQuery<RAY_FLAG_NONE>` local. Consequently it cannot escape into source
storage, a function ABI, or an ordinary value binding. Validation requires a
readonly acceleration structure, readonly inputs, a readwrite raw output, and
the compiler-owned ray-query capability; misuse receives SDSL-V4211 through
SDSL-V4213 diagnostics.

The emitted HLSL calls `TraceRayInline`, loops over `Proceed()`, checks
`CandidateType()`, gets the procedural primitive index, tests the analytic
sphere, calls `CommitProceduralPrimitiveHit(t)`, and reads committed status,
instance ID, geometry index, primitive index, `t`, barycentrics, and front
face. It is generated by the normal SDSL-V/VD-MIR/DXC route—there is no raw
HLSL source, handwritten SPIR-V, RT pipeline, or CPU production traversal.

Canonical compilation was:

```text
go run ./cmd/oct sdslv compile-spv internal/prometheus/shaders/sdslv/production/rayquery/ray_query_raw_hit.sdslv -o out/ray_query_raw_hit.spv --validate --require-spirv-val
```

DXC used `-spirv -T cs_6_5 -fspv-target-env=vulkan1.3 -O3`; `spirv-val`
accepted the output. Disassembly contains `OpCapability RayQueryKHR`,
`OpTypeRayQueryKHR`, `OpRayQueryInitializeKHR`, `OpRayQueryProceedKHR`,
`OpRayQueryGetIntersectionPrimitiveIndexKHR`, `OpRayQueryGenerateIntersectionKHR`,
and committed `t`, geometry, instance, barycentric, and front-face queries.

## Scene and ABI

`PrometheusRayQuerySphere` is finite Float32 center/radius/albedo plus a
material ID. Creation rejects non-finite fields, non-positive radii, non-finite
derived AABB bounds, absent geometry, and byte-count overflow. Each sphere
produces one 24-byte AABB `(min.xyz,max.xyz)` and a 32-byte shader record
`(center.xyz,radius)` / `(albedo.xyz,material)`.

Scenes may contain triangles, spheres, or both. Triangle geometry builds the
retained triangle BLAS; spheres build a separate procedural-AABB BLAS using
device-addressable AABB input, a 24-byte stride, size query, aligned scratch,
and a completed build submission. The TLAS has one identity instance per live
BLAS. Its build follows both BLAS submissions. Warm traces dispatch only; they
do not rebuild either BLAS or the TLAS. Destruction releases pipeline and
descriptor objects, TLAS, instance storage, procedural BLAS/AABB storage,
triangle BLAS/vertex storage, then host scene state.

`PrometheusRayQueryRawHit` is six 16-byte lanes (96 bytes), matching generated
SPIR-V offsets and stride exactly. `Meta` contains `(hit, kind, instance,
geometry)`; `TPrimitive` contains `(t, primitive bits, front-face, status
bits)`; the remaining lanes are position, normal, barycentrics, and
albedo/material. Miss uses `hit=kind=0`, instance/geometry `UINT32_MAX`,
`t=-1`, and barycentrics `(-1,-1)`.

Sphere intersection uses the Float32 quadratic `a=dot(d,d)`, `b=dot(oc,d)`,
`c=dot(oc,oc)-r*r`, discriminant `b*b-a*c`, and roots
`(-b ± sqrt(discriminant))/a`. This supports non-unit nonzero ray directions.
The nearest root in the closed `[TMin,TMax]` interval is committed; therefore
an AABB candidate that misses the true sphere is rejected. Sphere normals are
`normalize(hitPosition-center)`. Triangle normals are recovered from the
actual three vertex positions, not a fixed or AABB normal.

The RTX corpus exposed that procedural candidate visitation itself is not a
closest-hit policy. Generated HLSL now compares every legal analytic root with
the committed `t` and commits only when there is no committed hit or the new
root is strictly nearer. Overlapping spheres therefore select the exact nearest
primitive independently of candidate visitation order.

## Raw numerical qualification

The Marionette raw corpus now has an independent, test-only double-precision
authority. It uses Möller–Trumbore intersection for triangles, with source
winding `(a,b,c)`, normal `normalize((b-a)x(c-a))`, barycentrics `(u,v)` for
vertices `(b,c)`, and front face when `dot(normal,direction) < 0`. It uses the
full analytic quadratic above for spheres. Both use closed intervals; exact
cross-primitive ties are deliberately outside this checkpoint's ordering claim
and the fixtures use strict nearest winners.

All identity fields and miss sentinels compare exactly. Float quantities use
absolute-or-relative tolerance `2e-5`; the absolute branch deliberately
handles values near zero. On the RTX 3070 validation run the reported maxima
were: committed `t` `9.22933504e-7`, position component `9.22933504e-7`, and
normal component `9.22933504e-7`, all in `sphere-near-tangent-hit`; maximum
barycentric component error was `1.3038516e-8` in `triangle-interior-bary`.

The raw corpus covers triangle hit/miss/front/back/interior-barycentric/nearest
and interval cases; sphere exterior/miss/non-unit-direction/inside/behind/
interval/tangent/near-tangent/overlap cases; a procedural-AABB false positive
behind a real triangle; and mixed nearest-hit ordering. It additionally proves
warm raw equality, alternating two-live-scene isolation, destruction isolation,
and destroyed-handle rejection. Invalid nonfinite origins/directions/intervals,
zero directions, malformed output, invalid handles, and invalid sphere inputs
are rejected by the host boundary.

Practical Vulkan allocation/build/descriptor/dispatch fault injection is not
currently exposed by the owner; no broad test-only framework was added. Those
failure branches remain implementation-reviewed but un-injected. Triangle
nonfinite and degenerate validation remains covered by the retained triangle
scene route.
