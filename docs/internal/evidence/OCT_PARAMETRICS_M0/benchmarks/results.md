# Benchmark results

Host: Windows/amd64, AMD Ryzen 7 7700X. Commands use the opt-in `integration` build tag.

## Compile scaling

```text
scale  parse_ns  project_load_ns  monomorphize_ns  typecheck_ns  lower_emit_ns  generated_bytes  instantiations
1      515200    7792700          0                 519400        0              1399             1
10     0         2085000          0                 0             0              8480             10
100    1056400   10382000         0                 1036500       2678000        81954            100
```

Windows clock resolution rounds sub-millisecond phases to zero, so those cells mean below observable resolution, not free work. Instantiation count and generated bytes grow approximately linearly; 100 applications produce 100 specializations, not an exponential expansion.

## Runtime sanity

Five 500 ms samples over 10,000 records:

```text
handwritten ns/op: 46417, 65681, 72251, 68425, 68550
parametric  ns/op: 88394, 92019, 91765, 84040, 71847
both: 0 B/op, 0 allocs/op
```

This run's medians differ materially (68,425 versus 88,394 ns/op), so raw throughput is not claimed equal. The stronger compiler audit shows identical MIR after name normalization, and both paths allocate zero; there is no generic metadata, dictionary, reflection, or dispatch in either execution loop. The observed name/layout/order-sensitive Windows benchmark gap remains a measurement limitation to revisit, not evidence of a template runtime tax.
