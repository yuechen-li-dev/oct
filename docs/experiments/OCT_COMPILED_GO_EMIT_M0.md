# Compiled Oct embeddable Go emission M0

## 1. Result

**Success.** One ordinary Oct program containing a scalar-board admission
`flow` now passes through the existing compiled backend into a committed
sibling Go file. A handwritten Go test constructs and steps that generated
flow directly. Once generated, both `go test` and `go build` succeed with the
Oct source temporarily absent, so neither command executes Oct, OctGen, an
interpreter, or a generation hook.

This is an experimental internal seam, not an Oct 1.0 API or a generalized Go
metaprogramming surface.

## 2. Exact pipeline achieved

```text
experimental/octemit/specimen/controller/controller.oct
  -> project.Load
  -> typecheck.CheckProgram
  -> existing lowerProgram (Oct -> existing MIR)
  -> existing Go emitter in embeddable mode
  -> go/format
  -> controller.generated.go
  -> handwritten controller_test.go
  -> ordinary go test / go build
```

The explicit generation and freshness commands are:

```powershell
go run ./experimental/octemit generate -input experimental/octemit/specimen/controller/controller.oct -output experimental/octemit/specimen/controller/controller.generated.go -package controller
go run ./experimental/octemit check -input experimental/octemit/specimen/controller/controller.oct -output experimental/octemit/specimen/controller/controller.generated.go -package controller
```

The driver confines output to a sibling path ending in `.generated.go`. It is
not called by `go generate`, `go test`, or `go build`.

## 3. What changed in the compiler

`internal/build.EmitGoSource` is the new source-only seam. It performs normal
project loading, type checking, MIR lowering, and Go emission, then returns
formatted bytes without writing a file or invoking `go build`. Its one option
is the destination Go package name.

The former emitter is now a thin call to the same option-aware emitter with
`package main` and process-entrypoint emission enabled. Therefore normal
compiled Oct and embeddable output share all lowering, flow runtime, builtin,
record, enum, and function emission logic. No emitter logic was copied.

Embeddable mode differs in exactly three output properties:

- it uses the explicit destination package name;
- it omits the synthesized `func main()` process entrypoint;
- the source-only API formats the result and prepends
  `// Code generated by Oct's compiled backend. DO NOT EDIT.`.

The small experimental driver owns destination validation, writing, and byte
freshness checks. OctGen's checked-artifact code was not reused because that
package owns an interpreted-Oct model boundary and OctGen-specific diagnostics;
making it generic would tangle two experiments for a one-file check.

## 4. Independence proof

After generation, the source was moved from `controller.oct` to
`controller.oct.held` for the duration of these commands and restored in a
`finally` block:

```powershell
go test -count=1 ./experimental/octemit/specimen/controller
go build ./experimental/octemit/specimen/controller
```

Both passed. The package has no generation directive, init hook, repository
internal import, or runtime Oct dependency. The handwritten test calls the
generated `fn_Controller_AdmissionController`, `__octStep`, and `__octResult`
symbols directly.

Compatibility evidence for the unchanged standalone backend was:

```powershell
go test -count=1 -tags=integration -run 'TestCompileAndRunFlowCoreRuntimeBuiltins|TestCompileFlowBoardAndWhenActionBlock' ./internal/build
go run ./cmd/oct test Language/ControlFlow/OctomataCompiledBoundary/valid/compiled_boundary_core.octest --execution compiled --json
```

Both focused Go integration tests passed. The Oct corpus command reported one
compiled case, zero interpreted fallbacks, and one pass.

## 5. Determinism and freshness

Two explicit generations produced byte-identical 6,157-byte files with SHA-256:

```text
A8E990FA0DB976036D696349847A01311B640AEC4F8F9BA7BD8FD22D8BED761E
```

`TestGenerateCheckDeterminismAndStaleDetection` generates twice and compares
bytes, verifies clean check mode, mutates the generated file, and verifies that
check mode fails with `generated Go is stale`. The committed output contains no
timestamp, random value, absolute path, or ambient-machine value.

## 6. Limitations

- Generated identities are compiler-oriented and unexported. Same-package Go
  can use them directly, as this specimen does, but another Go package cannot.
- The constructor and control surface are currently
  `fn_Controller_AdmissionController`, `__octStep`, and `__octResult`; this is
  mechanically stable in the probe, not a designed public Go API.
- Although embeddable output has no Go `main`, lowering still requires the Oct
  entry package to contain `main` or `Main`. The specimen's `Main` is emitted as
  an unused ordinary function.
- Package naming is host-supplied rather than derived from the Oct package.
- The tiny flow emits 279 lines / 6,157 bytes, including generic clone, range,
  result, and assertion support that this specimen does not need. This is
  excessive runtime baggage, though it imports only Go standard-library
  packages (`fmt` and `reflect`) and remains buildable.
- There is no exported flow type alias or generated ergonomic facade. Adding
  one should be a separately bounded ABI/naming decision, not folded into this
  source-emission proof.

These limitations do not block a same-package database scheduling experiment:
handwritten Go can already own framework/database integration and call the
committed compiled-Oct controller directly. This milestone intentionally stops
before that experiment.
