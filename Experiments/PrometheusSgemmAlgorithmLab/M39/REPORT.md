## 3) Dispatch models simulated

Implemented functions:

- **A** `M39SimulateSingle` (single-worker baseline)
- **B** `M39SimulateStaticPartition` (central policy + static partition)
- **C** `M39SimulateSpmc` (central policy + shared SPMC)
- **D** `M39SimulateSteal` (central policy + local queues + stealing/backoff)
- **E** `M39SimulateParallelJudgment` (parallel judgment reference)

### Effective worker count and memory pressure

Computed by `M39EvaluateWorkers`:

```text
effective_workers = min(requested_workers, hardware_queue_count, floor(memory_budget_bytes / per_worker_arena_bytes))
```

Tracked per result:

- `EffectiveWorkers`
- `MemoryUsed`
- `MemoryLimited`
- `MemoryInfeasible`

When memory budget yields zero workers, configuration is infeasible.

## 7) Final answers (model-backed)

1. **Is centralized policy + immutable dispatch plans viable?**
   - **Yes**, in this model; viability holds when policy is not overwhelmingly dominant and worker count is capped by queue topology and memory.

2. **When does centralized policy bottleneck?**
   - When `N * JudgmentCost` dominates parallel dispatch lane time and overhead.

3. **Which dispatch model should be implemented first?**
   - Model-selected recommendation is **B (central policy + static partition)** for first implementation.

4. **Is work stealing necessary for the first implementation?**
   - **No** in the computed recommendation path.

5. **Under what workload does work stealing become worth it?**
   - Heavy-tail workloads where imbalance is sustained and steal/backoff overhead remains low enough for net score gain.

6. **How should worker count be chosen from queue topology and memory budget?**
   - `effective_workers = min(requested_workers, hardware_queue_count, floor(memory_budget_bytes / per_worker_arena_bytes))`.

7. **How should design degrade on single-queue hardware?**
   - Force parallel models to effective worker count `1`; no claimed parallel speedup.

8. **How does per-worker arena memory pressure affect worker count?**
   - It directly caps workers; if cap is zero, scenario is infeasible.

9. **What should P11 M5 / Lab M40 do next?**
   - Implement B-first path with instrumentation (policy vs dispatch vs event overhead), then gate C for measured variability.

10. **What should absolutely not be implemented yet?**
   - Full production work-stealing runtime, MPMC queue runtime, N-slot runtime, and full batch API.
